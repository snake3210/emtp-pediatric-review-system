### P0-1：所謂「PO 簽章」仍是可任意自行構造的**文字格式**，且 SHA／效期驗證可跳過
`R1BLivePermit.validate()` 只檢查 `approved_by` 含 PO、`permit_signature.startswith("PO_PRELIVE_SIGNOFF_TOKEN_")` 和長度；本輪測試直接提供固定字串 `PO_PRELIVE_SIGNOFF_TOKEN_VALID_SECURE_HASH_001` 即算有效。**沒有任何外部可信來源／秘密金鑰／驗證過的 PO 核准紀錄作為簽章真偽依據**，所以不能宣稱防偽已完成。另 `current_head_sha` 是可選，`R1BControlledHttpTransport._ensure_permit_and_safety()` 只呼叫無引數 `permit.validate()`；`run_controlled_pilot` 只傳 target_db，**執行時完全沒有取得/核對當前 Git HEAD**；`expires_at=None` 也合法。

**最小修法**：區分「Permit 欄位格式檢查」與真正「PO 已核准」；要有**外部已核對的 PO 決策憑據／可信 manifest**（明確交易日、2 URL、PR HEAD SHA、隔離 PostgreSQL DB、單次唯一 permit ID、期限）才能使 LIVE 入口啟用，且不得靠程式硬編碼可猜的 token 前綴或任意 `approved_by` 成立；驗證 HEAD 必須實際執行且期效必填。若目前還不能驗證可信批准憑據，**LIVE 入口先 hard-disable**，維持 Mock-only，別宣稱簽章有效。**不得自行產生 Gate B 核准憑據。**

### P0-2：跨程序持久額度 Ledger 排他鎖實際**Fail-Open**，且資料毀損會清空歷史
`R1BPreliveQuotaLedger.check_and_claim_quota()`：
```python
try: os.open(lock_file, os.O_CREAT | os.O_EXCL | os.O_WRONLY, ...)
except FileExistsError:
    pass  # 鎖已存在仍繼續讀/寫 ledger
...
except Exception:
    records = []  # JSON 讀取損壞竟重設額度！
...
tmp_ledger = ledger_path.with_suffix(".tmp")
tmp_ledger.write_text(...)
tmp_ledger.replace(ledger_path)
```
**兩個不同 session／不同 Python 行程同時使用同 permit_id** 時，第二個忽略鎖、同時讀舊 `records`，兩者均可能預占成功並各發一次 GET，違反 <=1 次/市場；還可能覆寫同一 `.tmp`。Ledger 損壞或讀失敗時恢復 `[]` 更危險。現有「跨程序」測試**只是在同一 Python 行程 new 第二個 Transport**，未測真正多進程競態。且直接建立沒有 ledger 的 `R1BControlledHttpTransport(mock_transport=None)` 目前仍可跳過持久預占，只受記憶體計數控制。

**最小修法**：預占改為**每個已授權 permit ID＋market 一份 O_EXCL 原子 claim 檔**或真正排他鎖覆蓋讀→檢查→寫→fsync 完整臨界區；鎖取得失敗／檔案無法解析／寫盤失敗一律 **NO GET / fail-closed**，永不回退空 ledger，崩潰後未判明的 claim 視為已耗盡。LIVE transport **沒有持久 ledger 一律不得出網**。補**真正兩個獨立 subprocess/multiprocessing 同時 claim 同一市場**的測試、損壞 ledger 負測、無 ledger 嘗試 LIVE 的負測；確認最後最多一方成功 claim，不需要真的連官方端點。

### P0-3：LIVE 啟用與來源／DB 邊界依然過早放行
- `R1BPreliveRunner.ensure_prerequisites()` 的 non-Mock 分支在發 GET **之前**即建立/升級 S-06/S-08 `LIVE_VERIFIED`，甚至 **HTTP 失敗仍可能留著 LIVE_VERIFIED**。HTTP 200 僅證明傳輸回應、不能單獨證明資料授權或獨立對帳。應先以 PENDING／UNVERIFIED 記錄，收到來源 bytes、核對交易日/資料後再按可證明等級更新，不得自動認列 `LIVE_VERIFIED` 或 OGDL 法律 clearance。
- `validate_r1b_target_db()` 仍無條件接受任意 SQLite（包括 SQLite 檔案庫），`R1BPreliveRunner._get_target_db_name()` 回 `sqlite`，而 Permit 可將 `sqlite` 自行加到 `allowed_databases`；**未阻斷 LIVE + SQLite 路徑**。請 LIVE 嚴格只准隔離 `twstock_demo/twstock_test` PostgreSQL；SQLite 只允許有 MockTransport 的離線單元測試。加兩個對應負測。
- TPEx 出現 HTTP 非 200／exception 時 `R1BPreliveResult.status` 可能留著預設 `FAILED_TWSE`，即使 TWSE 已 commit 成功；請順手改成正確 `PARTIAL_TWSE_ONLY`，讓 PO 能理解部分成功狀態。
